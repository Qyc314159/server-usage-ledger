# 服务器使用台账

> N 人共用 M 张卡（卡号 0–M-1）。**主要使用者：A、B**；第三人仅在本组任务之外使用。
> 本台账只保留 **今天 −3 天 ~ 今天 +3 天** 的记录，窗外条目自动清除。
> **人类只维护「填写区」；「AI 区」由 AI 读写，人类不要手改。**

## 一、使用说明（人读）

跑任务前先登记，跑完补实际。

- **要开跑** → 在「填写区」加一条，`status: planned`
- **跑起来** → 改成 `status: running`
- **跑完了** → 改成 `status: done`，补齐实际用时 / 卡号 / batch_size
- 只填能确认的；不确定就留空 —— **AI 不猜**

字段清单：日期 / 使用者 / 卡号 / 起止时间 / 时长 / 任务 / batch_size / 是否并行 / 并行方式 / 是否还有并行空间 / 状态 / 备注

## 二、AI 操作规范（机器读）

> 本节是给 **AI agent** 的执行规范，人类可跳过、不要修改。
> 完整版见 skill 的 `references/maintenance-rules.md`。

### 2.1 输入格式（AI 追加到「填写区」）

```yaml
- date: 2026-10-15          # 使用日期
  user: A                   # 使用者
  cards: [0, 1, 2, 3]       # 卡号
  start: "09:00"
  end: "18:00"
  hours: 9.0                # 时长（小时）
  task: "xxx 训练"
  batch_size: 64
  parallel: true            # 本次是否并行
  parallel_mode: "DDP 4卡"  # 并行方式（无则留空）
  can_parallel: true        # 是否还有并行空间 / 是否可并行
  status: planned           # planned | running | done
  note: ""
```

### 2.2 输出格式（AI 重写「AI 读取区」）

```yaml
window: ["2026-10-12", "2026-10-18"]
generated_at: "2026-10-15T10:00:00+08:00"
summary:
  total_card_hours: 128.0
  by_user: { A: 64.0, B: 64.0 }
  by_card: { 0: 16.0, 1: 16.0 }
conflicts: []        # 同卡同时段重叠
entries: []          # 规范化后的逐条记录
```

### 2.3 维护规则

1. **先读后写**：每次操作前重读文档最新内容
2. 追加 / 更新条目到「填写区」，按日期分组，条目标 `@user`
3. 重算并覆写「AI 读取区」（按 2.2 格式）
4. **清理窗口**：删掉早于「今天 −3 天」的条目；「今天 +3 天」以后的未来条目同样删除
5. **冲突检测**：同卡同时段重叠 → 写进 `conflicts`
6. 不硬删历史：移出正文前先让人类确认
